# 提示词：基于 OpenAPI 的 Python CLI 压测工具

## 项目目标
这是一个 Python 命令行工具，用户提供正在运行的 Java Spring 应用的 OpenAPI（Swagger）文档 URL（例如 `http://localhost:8101/api/v3/api-docs`），工具自动：
1. 解析所有接口（路径、HTTP 方法、请求参数/体 Schema）。
2. 根据 Schema 自动生成合法测试数据（支持 JSON 请求体、Query 参数、Path 参数）。
3. 对每个接口执行压力测试（可配置并发数、总请求数或持续时间）。
4. 收集每个接口的响应时间，计算 **P95** 和 **P99** 分位数。
5. 输出所有接口的 P95/P99 列表，**按 P95 从高到低排序**，并标明哪些接口因业务错误（如参数无效、依赖缺失）未能正确压测。


## CLI 输入参数
工具应支持以下命令行选项：
- `--openapi-url`（必需）：OpenAPI 文档的完整 URL，如 `http://localhost:8101/api/v3/api-docs`。
- `--concurrency`（可选，默认 10）：并发线程/协程数。
- `--total-requests`（可选，默认 1000）：每个接口的总请求数（或与 `--duration` 二选一）。
- `--duration`（可选）：压测持续时间（秒），若指定则忽略 `--total-requests`。
- `--output`（可选）：输出报告的文件路径（JSON 或 CSV），默认打印到控制台。
- `--skip-error-apis`（可选，默认 False）：若启用，则跳过冒烟测试失败的接口，只压测通过冒烟的接口。
- `--base-url`（可选）：覆盖 OpenAPI 中 `servers` 字段的 base URL（若文档中未定义或需替换）。

项目后续要支持其他语言项目的压力测试，所以此功能请单独开一个 Java 文件夹，将所有的功能都放进去。

## 核心功能模块

### 1. 解析 OpenAPI 文档
- 从给定 URL 获取 JSON。
- 提取 `paths` 下的所有端点，记录：
  - 路径（支持路径参数如 `/user/{id}`）
  - HTTP 方法（GET/POST/PUT/DELETE 等）
  - 请求参数（Query、Path、Header）
  - 请求体 Schema（`requestBody.content.application/json.schema`）
  - 响应定义（可选，用于验证业务成功）
- 同时读取 `components.schemas` 中的模型定义，用于生成请求体。

### 2. 自动生成测试数据
- 针对每个接口，根据 Schema 生成符合约束的 JSON 对象/Query 参数。
- 处理字段类型：
  - `string`：根据 `minLength`/`maxLength` 生成随机字符串（可用 `faker` 或 `random`）。
  - `integer` / `number`：生成范围内随机数。
  - `boolean`：随机 True/False。
  - `array`：生成含 1~3 个元素的数组，元素类型递归生成。
  - `object`：递归生成所有属性（若 `required` 标记则必须生成，非必填可选）。
- 对于路径参数（如 `{id}`），可从响应中获取（需支持依赖链），或预置测试数据（如 `1`），但若依赖其他接口，须智能处理。

### 3. 冒烟测试（预检）
- 正式压测前，以单线程（或低并发）对每个接口发送一次请求，使用自动生成的数据。
- 记录响应状态码和响应体（若为 JSON，检查业务状态码 `code` 字段是否为 0 或 200）。
- **判定“通过”**：HTTP 状态码 2xx 且业务码为成功（若存在）。
- 若失败，标记该接口为“参数错误/依赖缺失”，记录错误原因，后续压测可跳过（根据 `--skip-error-apis` 决定）。

### 4. 压力测试执行
- 仅对冒烟通过的接口进行压测。
- 使用协程（`asyncio` + `aiohttp`）或线程池并发发送请求。
- 每个接口独立运行，记录每次请求的响应时间（从发送到接收完整响应）。
- 请求过程中遇到连接错误、超时等，记录为错误，不计入百分位数计算。
- 支持动态调整并发数，但建议先固定并发。

### 5. 计算 P95 / P99
- 对每个接口的有效响应时间列表（排除错误请求）进行排序。
- 计算第 95 百分位数（索引 `int(0.95 * len)`）和第 99 百分位数。
- 若有效请求数不足（如少于 10 个），则标记为“数据不足”。

### 6. 输出报告
- 打印表格到控制台，包含：
  - 接口路径 + 方法
  - 状态（成功/跳过/失败）
  - P95 (ms)
  - P99 (ms)
  - 请求总数 / 成功数 / 失败数
- 按 P95 降序排列。
- 若指定 `--output`，同时生成 JSON 或 CSV 文件。

## 附加约束与设计建议
- **错误处理与重试**：因网络波动导致的连接错误，可重试最多 2 次，仍失败则记录。
- **超时设置**：每个请求设置超时（如 10 秒），超时计入失败。
- **依赖链处理（进阶）**：对于需要先注册、登录才能获取 token 或 ID 的接口，工具应支持“前置请求”定义。建议提供简单配置（如 YAML）让用户定义依赖关系，或通过分析 `operationId` 后缀（如 `create` 和 `delete`）自动推断。若复杂度高，可先不实现，但应在文档中说明。
- **数据清理**：为避免污染数据库，建议压测使用独立测试环境；工具本身不强制清理，但可提示用户。

## 非功能性需求
- **日志**：使用 `logging` 输出进度和错误，支持 `--verbose` 开启调试信息。
- **性能**：压测时尽量减少控制台输出，以免影响性能。
- **可扩展性**：代码结构清晰，便于后续添加更多数据生成策略或支持其他协议。
